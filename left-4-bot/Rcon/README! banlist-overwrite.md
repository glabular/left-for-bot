# Банлист `banned_user.cfg`: почему затирается и как чинить

Относится к `/ban` / `/unban` через RCON (`ServerBanService`: `banid` / `removeid`, затем `writeid`).

## Проблема

У Source/L4D2 два места для банов:

1. **Память** — то, что реально проверяется при входе (`listid`).
2. **Файл** `cfg/banned_user.cfg` — строки вида `banid 0 STEAM_…`. Сам по себе файл никого не банит, пока сервер его не выполнит.

`writeid` **полностью перезаписывает** файл тем, что сейчас в памяти. Бот вызывает `writeid` после каждого бана и разбана.

Если после старта (или смены карты) сервер **не загрузил** `banned_user.cfg` в память, память пустая или неполная. Следующий `/ban` (или меню SourceMod) добавляет один Steam ID и вызывает `writeid` → на диске остаётся только он. Старые ID из файла исчезают, даже если до этого файл был целым.

Типичный сценарий на хостинге (в т.ч. myarena): в `server.cfg` нет `exec banned_user.cfg`, после рестарта баны с диска не подхватываются, а следующий бан через бота затирает файл.

## Фикс на игровом сервере

В `server.cfg` добавьте (до любых `writeid` / `writeip`, если они есть):

```cfg
exec banned_user.cfg
exec banned_ip.cfg
```

`server.cfg` выполняется при старте и при смене карты — баны снова попадут в память до следующего `writeid`.

Порядок критичен только относительно `writeid`/`writeip`: сначала `exec`, потом запись. Относительно `hostname` и прочих cvar порядок не важен.

`writeid` в `server.cfg` для схемы «банит только бот» не обязателен: бот уже сохраняет список после `/ban` и `/unban`. Если добавите — только **после** `exec`, иначе пустая память затрёт файл ещё раньше.

## Если список уже затёрли

Восстановите `cfg/banned_user.cfg` из бэкапа или вручную верните строки `banid 0 STEAM_…`, затем перезапустите сервер (или выполните `exec banned_user.cfg` по RCON/консоли), чтобы они снова попали в память.

## Не путать

- Панель хостинга «Сохранить» для банлиста тоже часто перезаписывает файл целиком — не сохраняйте неполный список.
- Временные баны (`banid 60 …` и т.п.) в `banned_user.cfg` через `writeid` не живут; этот файл — про постоянные баны.
